# ClusterFlow

A skill for submitting and querying computational jobs on research group clusters.

本地开发到集群计算的可追溯工作流：先修改本地代码与输入，验证后冻结快照，再同步、提交、查询与记录。

> 当前版本：`0.1.0b1`，安装测试版。已实现初始化、项目绑定、检查与快照、SSH/SFTP、Slurm提交查询、下载、记录及受控取消/续算。自动测试使用模拟集群；你的真实账号、集群环境与科研数值结果仍需安装后验收，不能把测试通过等同于生产验证。

## 安装：把这段话发给你的 AI

使用能够访问本地文件和终端的 AI，将下面整段复制给它。无需自己先逐条执行安装命令。

```text
请帮我安装并初始化 ClusterFlow：
https://github.com/bo-qian/ClusterFlow

1. 检查本机系统、Python 环境和当前 AI 工具支持的 skill 安装方式。
   获取并审阅仓库 README、SKILL.md、references/commands.md，核对版本及实际能力。
   如果仓库缺少这些文件或当前版本不支持初始化，明确报告并停在可完成的步骤，
   不要临时补写初始化程序、调用旧工具冒充，也不要索要密码。
2. 使用当前工具支持的安装方式，部署完整 skill 和必需代码到合适的用户级位置。
   在私有虚拟环境安装本仓库依赖，使用仓库自带 scripts/install_skill.py 部署完整技能；
   安装目标按当前工具的文档核实，不能只复制 SKILL.md。
   复用可用环境，不覆盖已有本地修改，不擅自改全局配置；需要额外权限时先说明。
   验证工具能运行且当前 AI 能读取技能入口，不能把“下载了文件”当成安装成功。
3. 版本支持初始化后，集中询问缺少的连接信息：集群地址、端口、用户名、
   认证方式及是否需要 VPN/跳板机。密码只让我在本机隐藏输入，存入安全系统凭据库，
   不让我发到聊天里，不写入仓库、普通配置或日志；核对首次连接的服务器指纹。
4. 引导我绑定第一个项目：本地代码、集群代码、集群运行和本地结果目录，
   以及运行环境和 Slurm 资源偏好。已有信息复用，不猜测研究参数或覆盖已有文件。
5. 仅进行初始化所需的连接和只读环境检查，不上传项目代码、提交、取消或清理作业。
   最后分别报告：skill 安装、工具可运行、连接验证、项目绑定各自是否完成，
   配置保存位置（不含秘密），以及我下一次如何直接用自然语言操作。

如果当前 AI 不支持自动发现 skill，请说明限制并提供可用的显式入口；不要假称已注册。
```

这段提示词让 AI 带着你执行仓库里已有的程序，不是让它临时写另一套连接工具。安装、命令可运行、连接通过和项目绑定必须分别核实。密码需要你在可以直接操作的本机终端里隐藏输入；若 AI 的终端不支持人工输入，应让你在自己的终端运行初始化，而不是让你把密码发到聊天里。

安装器能部署完整技能，但不会假称所有 AI 自动发现机制相同；不支持自动发现时，使用部署目录里的 `SKILL.md` 作为显式入口。详细操作由 AI 阅读 [命令说明](references/commands.md) 后完成。

## 初始化时需要准备什么

初始化面向每个人自己的环境，不需要复制维护者的账号或目录。

| 信息 | 作用 |
|---|---|
| 集群地址、端口、用户名 | 确定连接目标；支持情况以版本说明为准 |
| 密码或 SSH 密钥认证方式 | 授权连接；秘密留在本机安全存储，不经聊天收集 |
| VPN／跳板机要求 | 确定本机是否能访问集群 |
| 本地代码与集群代码目录 | 确定代码从哪里修改、往哪里同步 |
| 集群运行与本地结果目录 | 分离代码、算例运行和下载结果 |
| 运行环境与资源偏好 | 使用自己的 Python/MPI、分区和资源配置 |

首次配置后复用；密码过期、设备或操作系统用户改变时，可能需要重新认证。支持密码、SSH agent、显式密钥和已初始化的跳板配置。VPN需自行连通；加密私钥建议交给SSH agent。Windows与WSL的凭据库不自动共享，推荐在Windows运行客户端并映射WSL源目录。

## 日常怎么用

完成相应功能的安装和初始化后，仍然直接用自然语言布置任务，不必每次重复账号和路径。例如：

- “把这个两颗粒算例的网格加密，检查后提交集群。”
- “新增这个功能，但不要改变之前算例的默认行为，测试通过再提交。”
- “看看 12345 算到哪里了，有没有异常。”
- “把这个任务的 CSV 和日志拉回来，暂时不要下载场数据。”
- “用上次冻结的代码和输入复现这个算例。”

AI 将这些要求转换成工具操作。只有明确提出算例提交时才提交；查询进度不会顺带修改代码或重跑任务。涉及方程、物理条件或旧结果可比性的歧义，仍须确认。

## 各部分做什么

本测试版实现以下操作，面向 Slurm，不绑定某个人、节点或科研模型。每个人初始化自己的配置，再验证自己的环境。

| 部分 | 功能与边界 |
|---|---|
| 初始化与认证 | 建立个人连接配置、核对主机指纹，通过系统凭据库复用认证，不明文保存密码 |
| 项目映射 | 将本地代码、远端代码、运行和结果目录关联起来；同一集群可绑定多个项目 |
| 本地修改与检查 | 先在本地修改代码或输入，调用科研项目自己的检查和回归测试；失败不提交 |
| 同步与快照 | 预览变更、检查远端冲突，冻结本次实际代码和输入；不默认删除或覆盖远端内容 |
| 提交与查询 | 核查资源后提交并记录 job ID，区分排队、运行、完成和失败；响应丢失先核查，不盲目重提 |
| 结果下载 | 默认获取输入、CSV、日志；图片、检查点和大场数据按需下载，中断文件不冒充完整结果 |
| 日志与追溯 | 关联研究目的、代码快照、输入、job ID、资源、状态和结果位置，换对话也有据可查 |
| 取消与续算 | 按明确指令操作，续算保留原 run 与新 execution 的关系，不覆盖历史证据 |

注意：续算的输入参数、检查点兼容性和CSV衔接由科研程序负责；本工具不自动改模型参数。应用的输出目录也要显式配置到代码快照之外，不能假定导出一个环境变量就会自动改写所有程序的输出路径。

总体流程：本地准备 → 检查 → 冻结快照 → 同步 → 提交 → 查询／取回结果／记录。

### 旧算例为什么还能复现

旧算例保留当时的代码、输入和环境说明；最新版增加功能时，通过科研项目的回归测试防止暗改旧行为。两者分别验收，不把“保存了旧版本”当成“最新版兼容”。数值结果按项目认可的容差检查，不承诺换环境后逐位相同。详见 [兼容性约定](references/compatibility.md)。

### 配置和数据放在哪里

- 可分享的 skill 与工具代码在本仓库，不携带个人实验历史。
- 个人连接配置保存在本机用户配置目录，秘密交给系统凭据库，不放仓库或 OneDrive。Windows默认位于`LOCALAPPDATA/clusterflow`。
- 算例输入、运行记录与结果索引归对应科研项目；大计算输出可以留在外部结果目录。
- 安装器更新时只替换未被修改的受管理部署，并留下旧版本备份；有本地修改就停止。Python环境依赖单独更新，不触碰个人配置、历史运行快照和科研代码。

## 开发与维护

已覆盖模拟传输与Slurm工作流、凭据存储接口、主机指纹变化、快照校验、回归失败、重复提交、提交响应丢失、结果大小限制和安装更新保护。安装测试应先做只读连接和小项目绑定，再由用户明确要求提交廉价测试算例；真实科研回归不能用这些工具测试代替。

当前59项测试已在Windows与WSL/Linux执行，平台／依赖不适用项有明确跳过记录，详见[验收边界与结果](references/validation.md)。

<details>
<summary>源码结构和本地开发命令</summary>

需要 Python 3.11 或更新版本，真实连接依赖Paramiko和keyring。安装到选定虚拟环境后，从仓库根目录执行：

```text
python scripts/clusterflow.py --version
python scripts/clusterflow.py status --json
python scripts/clusterflow.py doctor --json
python -m unittest discover -s tests -v
```

开发者可在自己的虚拟环境执行 `python -m pip install -e .`，随后使用 `clusterflow status --json`。这安装命令工具；完整skill部署另用`python scripts/install_skill.py --target <已核实的技能目录>/clusterflow`，然后核对AI是否发现或可显式读取该入口。不要把下载、工具安装和AI加载混为一步。

| 位置 | 用途 |
|---|---|
| `SKILL.md` | AI 操作入口，按需读取 references |
| `AGENTS.md` | 开发规范，不替代操作入口 |
| `src/clusterflow/` | 唯一工具实现 |
| `scripts/clusterflow.py` | 从源码直接运行的薄入口 |
| `scripts/install_skill.py` | 完整部署、更新检查与备份 |
| `references/` | 工作流、安全与兼容性约束 |
| `examples/` | 不含真实账号的未来配置示例 |
| `tests/` | 离线自动测试 |
| `agents/openai.yaml` | 可选的 Codex 界面元数据 |

安装到各 AI 工具中的部署版本不应成为第二份独立开发源码；更新时保留本地修改并核实版本。详细流程见 [工作流约定](references/workflow.md)。
