# ClusterFlow

用自然语言管理从本地代码到集群运行的完整算例流程。

可以直接使用集群已有代码，只上传本次算例输入；也可按需选择完整代码快照模式。

你描述要跑什么、改什么、查什么，AI 帮你准备本地代码和输入，检查后同步到集群、提交作业、查询进度并取回结果，不必每次重复账号和目录。

适用于 **Slurm 集群**，需要能访问本地文件和终端的 AI，以及 Python 3.11 或更新版本。

> 当前为试用版。首次使用请先验证自己的集群连接和运行环境，再提交一个小算例；确认正常后再用于正式任务。

## 安装：复制给你的 AI

将下面整段发给你的 AI，让它完成安装并引导你初始化：

```text
请帮我安装并初始化 ClusterFlow：
https://github.com/bo-qian/ClusterFlow

请先阅读仓库中的 README、SKILL.md 和配套安装说明，检查本机环境，
使用当前 AI 工具支持的方式安装完整技能及其依赖，并验证技能能够被读取、工具能够运行。
保留已有配置和本地修改，不擅自改全局环境；缺少必要权限或当前工具不支持时，请明确说明。

安装后，引导我配置集群连接和第一个项目，集中询问缺少的信息：
集群地址、端口、用户名、认证方式、VPN或跳板机要求，
本地与集群代码目录、运行和结果目录，以及运行环境和资源偏好。

密码只让我在本机终端隐藏输入，并保存到安全的系统凭据库。
不要让我把密码发到聊天里，不写入普通配置、仓库或日志。
首次连接时，引导我通过可信渠道核对服务器指纹，不自动接受未知指纹。

初始化只进行连接与只读环境检查，不上传代码、提交、取消或清理作业。
最后分别告诉我：安装、连接验证、项目绑定是否完成，以及下一次如何直接用自然语言操作。
如果有步骤无法完成，请说明原因和接下来需要我做什么，不要把未完成说成已完成。

```

密码输入需要你能直接操作的本机终端。如果 AI 的终端不支持人工输入，让它给出在你自己终端中运行的初始化步骤，**不要把密码发进聊天**。

不同 AI 工具加载技能的方式可能不同。如果不能自动发现，AI 应提供可用的显式入口，而不是仅下载文件就宣布安装成功。

## 初始化需要准备什么

| 信息 | 用途 |
|---|---|
| 集群地址、端口、用户名 | 确定连接目标 |
| 密码、SSH agent 或指定密钥 | 完成认证，秘密留在本机安全存储 |
| VPN／跳板机要求 | 确保本机能够访问集群 |
| 本地代码目录、集群代码目录 | 确定代码在哪里修改、同步到哪里 |
| 集群运行目录、本地结果目录 | 分开保存算例运行与下载结果 |
| 运行环境、启动方式、检查方式 | 使用项目自己的程序和检查流程 |
| 分区、CPU、内存等资源偏好 | 按集群要求申请计算资源 |

每个人配置自己的账号和路径；同一个集群可以绑定多个项目。配置完成后，后续任务会复用这些信息。

VPN 需要先自行连通。支持先配置跳板机，再通过它连接目标集群。加密私钥建议交给 SSH agent 管理。

## 日常怎么用

直接向 AI 描述任务即可，例如：

- “把这个两颗粒算例的网格加密，检查后提交集群。”
- “新增这个功能，但不要改变之前算例的默认行为，测试通过再提交。”
- “看看 12345 算到哪里了，有没有异常。”
- “把这个任务的 CSV 和日志取回来，暂时不要下载场数据。”
- “用上次冻结的代码和输入复现这个算例。”
- “从这个检查点继续计算，保留之前的运行记录。”

涉及方程、物理条件或旧结果可比性的歧义，AI 会先与你确认。查询进度不会顺带修改代码、重跑或取消任务。

## 功能说明

| 功能 | 你可以用它做什么 |
|---|---|
| 连接与认证 | 首次配置后复用连接信息，通过系统凭据库读取密码 |
| 项目映射 | 关联本地代码、集群代码、运行目录与结果目录 |
| 本地修改与检查 | 先修改本地代码或输入，再执行项目已有的检查；检查失败则不提交 |
| 同步与快照 | 预览要同步的内容，保存本次实际代码和输入，不覆盖已有冲突文件 |
| 提交与查询 | 检查资源、提交作业，查看排队、运行、完成或失败状态 |
| 结果下载 | 默认取回输入、CSV和日志；图片、检查点、大场数据按需下载 |
| 日志与追溯 | 记录输入、代码快照、作业编号、资源、状态和结果位置 |
| 旧算例复现 | 使用保留的旧代码和输入创建新运行，不误用当前已修改的代码 |
| 取消与续算 | 按明确指令取消作业，或关联原算例继续计算，保留各次执行记录 |

新算例通常按以下顺序处理：

**准备输入 → 检查 → 上传输入（按需同步代码）→ 提交 → 查询进度／取回结果。**

提交响应丢失时会先核查是否已经提交，不盲目再提交一次；远端出现冲突时停止，不默认删除或覆盖。

### 修改代码，会不会影响之前的算例？

完整快照模式保存独立代码和输入；集群现有代码模式只保存输入和代码版本信息，不冻结代码。后续本地修改不会自动替换已经提交的快照。

新增功能是否保持旧算例结果一致，需要项目自己的回归检查；保存了旧版本，并不意味着最新版自动兼容。复现旧版本也需要相应的外部依赖和环境仍然可用，换软件或硬件后不承诺数值逐位相同。

### 结果和记录放在哪里？

- 代码与输入快照、运行记录放在项目配置的记录目录。
- 下载结果放在项目配置的本地结果目录，大文件不要求搬进代码目录。
- 集群现有代码模式使用原工程，只为输入和结果建立独立运行目录；快照模式另建代码目录。
- 科研程序需要把输出明确写到代码快照之外；AI 会在项目绑定时与你核对。

续算的检查点、物理参数兼容性和数据衔接由科研程序负责。ClusterFlow 不会为了续算而擅自改动模型参数。

## 作业名称与编号

新作业使用能看懂的名称，例如 `MODEL_G1_240x160_dt0p01`，体现模型、算例、网格和步长。工具会附加一小段唯一标识，完整执行流水号留在追溯记录中。

作业名称、Slurm 分配的数字编号和科研程序的输出编号分别记录。科研程序原来按数字作业号建立输出目录和文件时，继续沿用原规则；已有作业和续算目录保持兼容，不为统一显示名称重新计算。

提交前还应核对本次采用的代码版本，包括求解和图片输出。项目可列出需要一致的文件；本地与远端不一致时，工具会阻止提交，先完成经授权的更新和检查。“只上传输入”不代表可以忽略已经发现的旧代码。

## 账号、配置与安全

- 密码保存在系统凭据库，不放聊天、普通配置文件、代码仓库或日志。
- 连接和路径配置保存在本机用户配置目录，不与可分享的技能混在一起。
- 更换 AI 账号一般不需要重新配置；换电脑、操作系统用户或运行环境时可能需要重新初始化。
- Windows 与 WSL 的凭据库不自动共享；可以在 Windows 运行客户端并使用 WSL 源目录。
- 系统凭据库不可用时，不会降级为明文保存，可以改用 SSH agent。
- 服务器指纹变化时会停止连接，需要先核实原因。

## 常见操作

**密码变了怎么办？**

告诉 AI：“更新这个集群的登录密码。”它会引导你在本机安全输入并验证。

**要增加另一个项目怎么办？**

告诉 AI 新项目的本地和集群目录、启动与检查方式，绑定到已有连接即可。

**怎么更新 ClusterFlow？**

告诉 AI：“更新 ClusterFlow，保留我的配置和历史记录。”已有安装存在本地修改时会停止，正常更新会保留旧版本备份。运行环境中的依赖需一并核对。

**遇到错误怎么办？**

让 AI 检查错误、运行记录和作业状态，不要直接重复提交。分享报错时去掉密码、私钥和其他敏感信息。
